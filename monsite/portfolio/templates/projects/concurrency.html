Inside the project

Seven ways to explore concurrency.

Small, focused examples turn abstract threading concepts into observable behavior, with logs that help follow each scenario.

01 / THREADS
λ

Parallel computation

Split a summation task across worker threads, join them and combine the partial results.

02 / MUTEX
⌁

Thread-safe logging

Protect shared log data with a mutex to demonstrate controlled access to shared state.

03 / TIMING
↗

Performance benchmark

Measure elapsed execution time and introduce the basics of runtime measurement.

04 / WAITING
◷

The sleeping barber

Explore waiting queues, customer arrival, condition variables and resource coordination.

05 / QUEUES
↕

The elevator

Model floor requests arriving concurrently and the coordination of an elevator worker.

06 / RESOURCES
▤

The shared buffet

Simulate competing consumers, a limited resource pool and replenishment events.

07 / SIGNALS
⌁

The lighthouse

Observe a changing signal and ship threads reacting to shared state over time.

Engineering focus

More than just starting threads.

The useful part of concurrency is coordination: deciding how threads share resources, wait, and finish predictably.

What this project demonstrates

  • ✓Creating and joining threads with the C++ standard library.
  • ✓Protecting shared data using mutexes and lock guards.
  • ✓Coordinating activity with condition variables and queues.
  • ✓Separating scenarios into focused source and header files.

Build it locally

Requirements: a C++20-compatible compiler and CMake 3.26 or later.

# Configure the project
cmake -S . -B build

# Build the executable
cmake --build build

The build output is generated in the build directory.
