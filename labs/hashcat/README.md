# Hashcat Password Auditing Lab

An isolated, reproducible lab for auditing **synthetic test hashes only** with Hashcat in Docker. No real account hashes, leaked credential lists, or third-party systems are needed.

## Scope

- Generate known MD5 and SHA-256 hashes from a tiny, explicitly synthetic fixture.
- Run dictionary attacks against those hashes.
- Compare a fast legacy hash (MD5) with SHA-256 while discussing why neither is recommended for password storage.
- Record runtime, recovered count, Hashcat version, host OS, and hardware. Results are intentionally not pre-filled: capture your own measurements.

> Safety boundary: use only the hashes generated by `python scripts/generate_fixtures.py`. Do not substitute hashes from real users or services.

## Requirements

- Docker Engine or Docker Desktop with Compose v2
- Python 3.10+ on the host (only for generating fixtures)
- Internet access on first run to pull `hashcat/hashcat`

GPU access is host-dependent. The baseline commands may use CPU or whatever devices the container can access; do not assume GPU acceleration. Record `hashcat -I` output and note if no usable device is detected.

## 1. Generate synthetic fixtures

From this directory:

```bash
python scripts/generate_fixtures.py
```

This creates `lab/hashes-md5.txt`, `lab/hashes-sha256.txt`, and `lab/wordlist.txt`. The fixture passwords are deliberately simple examples and are not real credentials.

## 2. Verify the container and version

```bash
docker compose run --rm hashcat --version
docker compose run --rm hashcat -I
```

If device initialization fails, save the error as a limitation. Do not report a benchmark as completed if Hashcat did not start successfully.

## 3. Run the dictionary audit

MD5 (`-m 0`):

```bash
docker compose run --rm hashcat -m 0 -a 0 /lab/hashes-md5.txt /lab/wordlist.txt --potfile-path /lab/md5.pot --outfile /lab/md5-recovered.txt
```

SHA-256 (`-m 1400`):

```bash
docker compose run --rm hashcat -m 1400 -a 0 /lab/hashes-sha256.txt /lab/wordlist.txt --potfile-path /lab/sha256.pot --outfile /lab/sha256-recovered.txt
```

Inspect the recovered output files under `lab/`. A recovered value is expected only if its known synthetic password appears in the supplied wordlist and the hash type is configured correctly. Treat actual command output as the source of truth.

## 4. Advanced experiment: controlled wordlist change

1. Copy `lab/wordlist.txt` to `lab/wordlist-expanded.txt`.
2. Add one additional synthetic candidate that you intentionally used when generating a test hash.
3. Run the corresponding command with the expanded wordlist and a separate potfile/output file.
4. Compare recovered count and elapsed time. Keep all other conditions constant.

Do not compare timings across different machines as if they were equivalent. For a fair comparison, record device, Hashcat version, hash count, wordlist size, and command line.

## 5. Evidence to capture

- Hashcat version and device information (`--version`, `-I`)
- Fixture generation command and a sanitized listing of file names/counts
- Exact command lines and complete terminal output
- Recovered-count comparison for MD5 and SHA-256
- Host OS, Docker version, CPU/GPU model, elapsed time
- Limitations, including device availability and small test sample size

Never publish secrets, private hashes, or unrelated personal data. The supplied fixture is safe to publish, but the exercise demonstrates only a tiny dictionary attack—not the security of every password or the strength of SHA-256 for password storage.

## Interpretation

MD5 and SHA-256 are fast general-purpose hash functions, so an attacker can test many guesses quickly. SHA-256 is not a password-storage function simply because it is newer than MD5. Prefer password-specific algorithms such as Argon2id, scrypt, or bcrypt with suitable parameters and unique salts.

```bash
docker compose down --remove-orphans
```
